Q 1.2: How does an Admin inspect and verify newly submitted physical equipment?
--------------------------------------------------------------------------------
STEPS VIA WEB UI / API:
1. In the Admin Portal, click on "Assets" -> "Assets" (or open Swagger: http://127.0.0.1:8000/api/docs/).
2. Select any Asset with verification_status = "PENDING" or "UNDER_REVIEW".
3. Check the physical serial number (e.g. SN-SONY-FX3-7712) and replacement value.
4. Set "Verification status" to "VERIFIED" and set "Status" to "AVAILABLE".
5. Or via REST API:
   POST /api/admin-ops/verify-asset/{asset_id}/
   Headers: Authorization: Bearer <ADMIN_JWT_TOKEN>
   Body:
   {
     "status": "VERIFIED",
     "admin_notes": "Serial number cross-referenced with manufacturer invoice. Verified."
   }
EXPECTED RESULT:
- Asset verification status updates to VERIFIED.
- An immutable entry is written to AuditLogEntry with old/new values and timestamp.
- Owner receives an instant notification that their equipment is verified and live.

Q 1.5: How does an Admin arbitrate a damage dispute and split the escrow deposit?
--------------------------------------------------------------------------------
STEPS:
1. Send a POST request to /api/admin-ops/arbitrate-dispute/ via Swagger:
   POST http://127.0.0.1:8000/api/admin-ops/arbitrate-dispute/
   Headers:
     Authorization: Bearer <ADMIN_TOKEN>
     Content-Type:  application/json
   Body:
   {
     "damage_report_id": 1,
     "owner_deduction_amount": 3500.00,
     "arbitration_notes": "Fair assessment: small ding on tripod mount. ₹3,500 allocated to Owner for repair, remaining deposit refunded to Renter."
   }
EXPECTED RESULT:
- SecurityDeposit transitions to PARTIALLY_DEDUCTED.
- LedgerService records 2 double-entry entries:
  1. DEPOSIT_DEDUCTED: ₹3,500 from SECURITY_DEPOSIT_ESCROW -> OWNER_PAYABLE
  2. DEPOSIT_RELEASED: Un-deducted balance from ESCROW -> RENTER_BANK_ACCOUNT
- Both Owner and Renter receive arbitration resolution notifications.
